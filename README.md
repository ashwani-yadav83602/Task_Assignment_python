# TaskFlow — Internal Task & Management Dashboard

An internal task-tracking application built to demonstrate full-stack development: a React/Vite frontend, a FastAPI backend, JWT authentication, backend-driven filtering/pagination, and an external API integration.

## Project Overview

TaskFlow lets a team create, assign, track, and comment on tasks from a central dashboard. It includes:

- A dashboard with live task counts (total, pending, in progress, completed, overdue, assigned to me)
- Full task CRUD with priority, status, due dates, and comments
- A searchable, filterable, paginated task list (filtering/sorting/pagination handled server-side)
- Role-based JWT authentication (admin / member)
- An external API integration (JSONPlaceholder) surfaced under `/api/external/users`

## Tech Stack

**Frontend:** React 19, Vite, Tailwind CSS, React Router v7, lucide-react
**Backend:** Python, FastAPI, SQLAlchemy, Pydantic, Alembic
**Database:** SQLite (default, zero-config for local dev — see Assumptions)
**Auth:** JWT (PyJWT) with bcrypt password hashing

## Setup Instructions

### Prerequisites
- Node.js 18+
- Python 3.11+

### 1. Clone the repo
```bash
git clone https://github.com/ashwani-yadav83602/Task_Assignment_python.git
cd Task_Assignment_python
```

### 2. Backend setup
```bash
cd Backend
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

### 3. Database setup
The default configuration uses SQLite, so no separate database server is required.

Run migrations:
```bash
alembic upgrade head
```

Seed the database with demo users and tasks:
```bash
python -m app.seed
```
This creates three users (see credentials below) and five sample tasks with comments so the dashboard has real data on first load.

### 4. Run the backend
```bash
uvicorn app.main:app --reload
```
API available at `http://localhost:8000`. Interactive API docs (Swagger UI, auto-generated by FastAPI) at `http://localhost:8000/docs`.

### 5. Frontend setup
```bash
cd ../Frontend
npm install
```

### 6. Run the frontend
```bash
npm run dev
```
App available at `http://localhost:5173`.

## Environment Variables

Set in `Backend/.env` (see `Backend/.env.example`):

| Variable | Description | Default |
|---|---|---|
| `DATABASE_URL` | SQLAlchemy connection string | `sqlite:///./tasks.db` |
| `JWT_SECRET` | Secret used to sign JWTs — change in production | `change-me-in-production` |
| `JWT_EXPIRE_MINUTES` | Token lifetime in minutes | `480` |
| `CORS_ORIGINS` | Comma-separated allowed origins | `http://localhost:5173` |
| `EXTERNAL_API_URL` | Base URL for the external API integration | `https://jsonplaceholder.typicode.com` |
| `EXTERNAL_API_TIMEOUT` | Timeout (seconds) for external API calls | `8.0` |

The frontend's API base URL is set directly in `Frontend/src/services/api.js` (`http://localhost:8000/api`) — update it there if the backend runs elsewhere.

## API Documentation

Full interactive docs are auto-generated at `/docs` (Swagger UI) once the backend is running. Summary of endpoints:

**Auth**
- `POST /api/auth/login` — returns `{ access_token, token_type, user }`
- `GET /api/auth/me` — current authenticated user

**Users**
- `GET /api/users` — list users
- `POST /api/users` — create a user (admin only)

**Tasks**
- `GET /api/tasks` — list tasks, supports:
  - `status`, `priority`, `assignee`, `search`
  - `sort_by`, `sort_dir`
  - `page`, `limit`
- `GET /api/tasks/{id}` — task detail (includes assignee and comments)
- `POST /api/tasks` — create a task
- `PUT /api/tasks/{id}` — update a task
- `DELETE /api/tasks/{id}` — delete a task
- `POST /api/tasks/{id}/comments` — add a comment to a task

**Dashboard**
- `GET /api/dashboard` — aggregated stats: total/pending/in-progress/completed/overdue tasks, plus tasks assigned to the current user

**External integration**
- `GET /api/external/users` — proxies JSONPlaceholder, demonstrates timeout handling and response mapping

All endpoints (except login) require a `Authorization: Bearer <token>` header. Requests are validated with Pydantic; errors return standard HTTP status codes (400/401/403/404) with a JSON `detail` message.

## Database Schema

- **users**: id, name, email (unique), hashed_password, role (admin/member), created_at
- **tasks**: id, title, description, status, priority, assigned_to (FK → users), created_by (FK → users), due_date, created_at, updated_at
- **comments**: id, task_id (FK → tasks, cascade delete), user_id (FK → users), comment, created_at

Migrations are managed with Alembic (`Backend/alembic/versions/`).

## Assumptions

- **SQLite over PostgreSQL**: SQLite was used for local development simplicity, per the assignment's note that it's acceptable. Since the backend uses SQLAlchemy, switching to PostgreSQL only requires updating `DATABASE_URL` and installing a Postgres driver (e.g. `psycopg2-binary`).
- **JWT authentication added beyond the base spec**: Login/authentication was listed as a bonus feature but was implemented as a core requirement here, since every route is protected. Two roles exist — `admin` (can manage users, delete any task) and `member` (can manage tasks they created or are assigned to).
- **Task creation/edit permissions**: A task can be updated by its creator, its assignee, or an admin; deletion is restricted to the creator or an admin.
- **External API**: JSONPlaceholder was used as a stand-in "external directory" since it requires no API key and is publicly available, while still demonstrating timeout and error handling.
